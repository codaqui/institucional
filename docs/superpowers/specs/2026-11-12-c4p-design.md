# C4P — Chamada de Trabalhos integrada (Fase 7, backend 1.0.0)

## Contexto e objetivo

O sistema externo de C4P (tRPC + Hono + MySQL, sem testes, auth por senha caseira) operou de fato o DevPR Conf 2026: importação CSV de Google Forms, avaliadores votando com 5 sliders 0–10, dashboard e finalização com PDF. Esta fase o porta para o monorepo (NestJS + TypeORM/PostgreSQL, auth nativa, audit, Turnstile) e adiciona o que ele não tinha: **submissão pública** de propostas (substituindo o Google Forms), critérios configuráveis por campanha e resultado público opt-in.

Backend: módulo `c4p/` novo, migration **049**, versão **1.0.0** (marco do plano-mãe). Frontend: páginas Astro novas (públicas com `PublicLayout`, gestão com `AppLayout`), ilhas React/MUI, snapshot estático no pattern `static/events/`. ADR 012 nasce com esta fase.

## Decisões de escopo (conflitos resolvidos e desvios de rota)

1. **Finalização é só `admin`.** O anexo `c4p.md` diz que `event_organizer` finaliza; a matriz do `rbac.md` (2026-10-29, mais recente e autodeclarada contrato das fases) diz "Finalizar campanha + PDF — admin". **Vence o rbac.md.** Gestão (CRUD, import, convites) fica com `admin`, `event_organizer`, `diretor` e responsável da comunidade dona da campanha.
2. **Rotas de app usam query param, não path dinâmico.** O build é 100% estático; rotas como `/c4p/avaliar/<callId>` e `/admin/c4p/<id>` não são enumeráveis em build. Segue o padrão da casa (`/eventos/detalhe`, `/admin/eventos?institutionId=`): `/c4p/avaliar/votar?call=<uuid>` e `/admin/c4p/detalhe?id=<uuid>`. As rotas públicas `/c4p`, `/c4p/<slug>/submeter` e `/c4p/<slug>/resultado` são estáticas geradas do snapshot (slugs conhecidos em build).
3. **Snapshot entra no escopo.** O anexo marca a página de resultado como "candidata a snapshot"; adotamos o pattern completo da casa (`static/c4p/index.json` + workflow de sync + proxy exception + leitura em build), igual a events/assemblies/announcements. Sem ele, campanha nova só teria página após rebuild manual.
4. **Importação CSV é parseada no backend.** O sistema externo parseava no browser (papaparse). Aqui o frontend lê o arquivo como texto e envia `text/csv` (padrão `importParticipants` de eventos); o parser e o mapeamento de cabeçalhos vivem no backend, testáveis em jest. Nenhuma dependência nova de CSV.
5. **E-mails de resultado são fire-and-forget.** A finalização dispara os envios sem `await` (cada `sendTemplate` nunca lança e passa pela fila global serializada do `EmailService`); `email_logs` registra cada um. Uma fila persistente (pattern ADR 016) é overkill para um disparo único por campanha e fica como follow-up se o volume crescer.
6. **`jspdf-autotable` é a única dependência nova** (frontend). `jspdf` já existe (DonationReceiptPdf). O anexo sanciona o par "jspdf + autotable" para o relatório no cliente.
7. **Voto de avaliador removido permanece contando** no score (comportamento do externo: `active=false` só sai do progresso, não da média). Remoção não apaga votos.
8. **Slug de campanha tem reserva de palavras**: `public`, `manage`, `evaluator`, `avaliar` — colidiriam com os prefixos de proxy ou as rotas de app (lição I-1 do AGENTS.md).

## Modelo de dados (migration 049)

Três tabelas novas + um índice único parcial em `member_designations` (os enums `c4p_campaign`/`evaluator` já existem desde a migration 026; **o índice de unicidade por campanha NÃO existe e é criado aqui** — a premissa de que ele já existia estava incorreta).

```sql
CREATE TABLE c4p_calls (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  slug varchar(80) NOT NULL,
  name varchar(160) NOT NULL,
  description text,
  managedEventId uuid REFERENCES managed_events(id),
  communityId uuid REFERENCES communities(id),
  status varchar(16) NOT NULL DEFAULT 'draft',        -- draft | open | closed
  submissionOpenAt timestamptz,
  submissionCloseAt timestamptz,
  criteria jsonb NOT NULL,                            -- Criterion[] (default DEFAULT_CRITERIA)
  selectedTalkIds jsonb,                              -- uuid[] (só quando closed)
  publicResults boolean NOT NULL DEFAULT false,
  finalizedAt timestamptz,
  createdById uuid NOT NULL,
  createdAt timestamptz NOT NULL DEFAULT now(),
  updatedAt timestamptz NOT NULL DEFAULT DEFAULT now(),
  CONSTRAINT UQ_c4p_calls_slug UNIQUE (slug),
  CONSTRAINT CK_c4p_calls_status CHECK (status IN ('draft','open','closed'))
);
CREATE INDEX IDX_c4p_calls_status ON c4p_calls (status);

CREATE TABLE c4p_talks (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  callId uuid NOT NULL REFERENCES c4p_calls(id) ON DELETE CASCADE,
  speakerName varchar(160) NOT NULL,
  speakerEmail varchar(160) NOT NULL,
  speakerPhone varchar(60),
  speakerRole varchar(200),
  linkedin varchar(255),
  spokeBefore boolean,                                -- null = não informado
  title varchar(255) NOT NULL,
  summary text NOT NULL,
  level varchar(40),
  track varchar(255),
  bio text,
  photoUrl varchar(2000),
  extraNotes text,
  origin varchar(16) NOT NULL,                        -- public_form | csv_import
  consentAt timestamptz,                              -- obrigatório quando origin='public_form'
  createdAt timestamptz NOT NULL DEFAULT now(),
  updatedAt timestamptz NOT NULL DEFAULT DEFAULT now(),
  CONSTRAINT CK_c4p_talks_origin CHECK (origin IN ('public_form','csv_import'))
);
CREATE INDEX IDX_c4p_talks_call ON c4p_talks (callId);

CREATE TABLE c4p_votes (
  id uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
  talkId uuid NOT NULL REFERENCES c4p_talks(id) ON DELETE CASCADE,
  evaluatorDesignationId uuid NOT NULL REFERENCES member_designations(id),
  scores jsonb NOT NULL,                              -- { [criterionKey]: 0..10 }
  comment text,
  createdAt timestamptz NOT NULL DEFAULT now(),
  updatedAt timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT UQ_c4p_votes_talk_evaluator UNIQUE (talkId, evaluatorDesignationId)
);

-- 1 avaliador active por (campanha, membro) — garantia em banco; o service valida antes p/ mensagem amigável
CREATE UNIQUE INDEX UQ_member_designations_c4p_evaluator
  ON member_designations (targetId, memberId)
  WHERE targetType = 'c4p_campaign' AND designation = 'evaluator' AND status = 'active';
```

Entidades TypeORM espelham o DDL (padrão `announcement.entity.ts`: `@PrimaryGeneratedColumn('uuid')`, `CreateDateColumn`/`UpdateDateColumn` timestamptz, FKs por coluna). Melhorias deliberadas sobre o externo: e-mail do palestrante obrigatório e validado (externo era opcional sem formato), `spokeBefore` boolean (externo era texto livre "Sim"/"Não"), `selectedTalkIds` jsonb nativo (externo serializava JSON em text).

## Critérios configuráveis e scoring

```ts
interface Criterion { key: string; label: string; weight: number }
```

Default (os 5 do externo, pesos iguais — peso é relativo, não precisa somar 100):

```json
[
  { "key": "relevancia",  "label": "Relevância Prática e Alinhamento",  "weight": 1 },
  { "key": "viabilidade", "label": "Viabilidade no Palco Único",        "weight": 1 },
  { "key": "clareza",     "label": "Clareza do Resumo e Escopo",        "weight": 1 },
  { "key": "inovacao",    "label": "Inovação e Domínio do Tema",        "weight": 1 },
  { "key": "diversidade", "label": "Diversidade e Equilíbrio da Grade", "weight": 1 }
]
```

Validação de critérios (no service, ao criar/editar): 1–10 critérios; `key` única, `/^[a-z][a-z0-9_]{0,30}$/`; `label` 3–80; `weight` inteiro ou decimal > 0 e ≤ 100; soma dos pesos > 0. **Critérios são editáveis somente enquanto a campanha não tem nenhum voto** (depois, 409) — chave de score gravada não pode mudar de significado.

Scoring (funções puras em `c4p/c4p-scoring.ts`, testadas em jest):

- **Score do voto**: `Σ(score_c × peso_c) / Σ(peso_c)` apenas sobre os critérios presentes no voto ("critérios sem voto não entram no cálculo individual"). Voto sem nenhum critério é inválido (400).
- **Nota da palestra**: média aritmética simples dos scores dos votos. Palestra sem voto tem `avgTotal = null` e afunda no ranking.
- **Médias por critério**: para cada critério, média dos scores entre os votos que o preencheram.
- **Arredondamento só na apresentação** (2 casas; PDF usa `toFixed(2)` na média e `toFixed(1)` por critério), igual ao externo.
- **Ranking**: `avgTotal` desc, posição 1-based; empates mantêm ordem estável; flag `selected`.

## APIs (públicas, avaliador, gestão)

Sem prefixo global. Gestão **não** usa `/admin/`. Erros seguem o padrão Nest (`{ statusCode, message }`). Toda rota autenticada usa `JwtAuthGuard` + checagem de papel/designation **no service** (pattern ownership de eventos — o guard de roles não expressa vínculo de comunidade).

### Públicas (sem auth; ThrottlerGuard global + regra extra na submissão)

| Rota | Descrição |
|---|---|
| `GET /c4p/public/calls` | Campanhas `open` dentro da janela (ou sem janela): `slug, name, description, submissionOpenAt, submissionCloseAt, community {slug,name}\|null, event {slug,title}\|null` |
| `GET /c4p/public/calls/:slug` | Detalhe para a ilha de submissão validar o estado ao vivo (mesmos campos + `status`); 404 se desconhecida |
| `GET /c4p/public/calls/:slug/results` | 404 a menos que `publicResults=true` E `closed`; retorna `{ slug, name, finalizedAt, talks: [{ title, speakerName, track, level }] }` — **somente selecionadas, sem notas, sem comentários, sem contato** |
| `POST /c4p/public/calls/:slug/submissions` | Submissão pública (abaixo) |
| `GET /c4p/public/snapshot` | Payload completo do snapshot (fonte do sync) |

**Submissão** (`POST .../submissions`): `@UseGuards(TurnstileGuard)` com `@TurnstileAction('c4p_submission')` + `@Throttle({ default: { limit: 5, ttl: 60_000 } })`. Body: `speakerName` (1–160), `speakerEmail` (e-mail válido, ≤160), `title` (1–255), `summary` (1–20000), opcionais `speakerPhone` ≤60, `speakerRole` ≤200, `linkedin` (URL https sem credenciais, ≤255), `spokeBefore` boolean, `level` ≤40, `track` ≤255, `bio` ≤20000, `photoUrl` (URL https sem credenciais, ≤2000), `extraNotes` ≤20000, `consent: true` (literal — ausente/false → 400), `turnstileToken`. Regras: campanha existe (404 senão); `status='open'` e agora dentro da janela (se definida) — senão **409 "Esta chamada não está aceitando submissões."**. Grava `origin='public_form'`, `consentAt=now()`. Resposta **201 `{ id }`** sem eco de PII. Efeitos: e-mail de confirmação ao palestrante (fire-and-forget). Submissão duplicada (mesmo e-mail+título) é permitida — a curadoria remove a menor.

### Avaliador (JWT; designation `evaluator` @ campanha)

| Rota | Descrição |
|---|---|
| `GET /c4p/evaluator/calls` | Minhas designations (`pending` + `active`) com resumo da campanha: `{ designationId, status, call: { id, slug, name, status } }` |
| `POST /c4p/evaluator/designations/:id/accept` | Aceite do próprio membro: `pending → active` (via `DesignationsService.confirm` com actor = self); 404 se não é minha, 409 se não está `pending` |
| `GET /c4p/evaluator/calls/:callId` | Campanha + critérios + meu progresso `{ voted, total }`; exige designation `active` (403) |
| `GET /c4p/evaluator/calls/:callId/talks` | Propostas da campanha com meu voto embutido: `{ id, title, summary, level, track, speakerName, speakerRole, linkedin, bio, photoUrl, spokeBefore, myVote: { scores, comment, updatedAt } \| null }` |
| `PUT /c4p/evaluator/calls/:callId/talks/:talkId/vote` | Upsert do voto (abaixo) |

**Voto** (`PUT .../vote`): exige designation `active` na campanha (403) e campanha `open` (409 "A votação está encerrada nesta chamada."). Body: `scores: Record<string, number>` — chaves ⊆ critérios da campanha (chave extra → 400), cada valor **inteiro 0–10**, ao menos 1 critério; `comment` opcional ≤2000. Talk deve pertencer à campanha (404). Upsert por `ON CONFLICT (talkId, evaluatorDesignationId) DO UPDATE` (TypeORM `.orUpdate`/`upsert`), atualizando `scores`, `comment`, `updatedAt`. Retorna o voto salvo.

### Gestão (JWT; `assertCanManage`: `admin`/`event_organizer`/`diretor`, ou `responsible` @ community dona da campanha)

| Rota | Descrição |
|---|---|
| `GET /c4p/manage/calls?page&limit&status` | Lista paginada (envelope `PaginatedResultDto`) com contagens `talksCount, evaluatorsActiveCount, votesCount` |
| `POST /c4p/manage/calls` | Cria em `draft`: `slug` (regex `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`, reservados `public\|manage\|evaluator\|avaliar`, único), `name` 3–160, opcionais `description` ≤2000, `managedEventId` (existe), `communityId` (comunidade existe e ativa), `submissionOpenAt/CloseAt` (fim > início), `criteria` (validação acima), `publicResults` |
| `GET /c4p/manage/calls/:id` | Detalhe completo + contagens |
| `PATCH /c4p/manage/calls/:id` | `name/description/window/publicResults/managedEventId/communityId/criteria` (critérios só sem votos, senão 409) e `status: draft→open` (única transição via PATCH; `open→closed` só por finalize; `closed→open` só por reopen) |
| `POST /c4p/manage/calls/:id/talks/import` | Body `text/csv` (parser abaixo); retorna `{ imported, skipped: [{ line, reason }] }` |
| `GET /c4p/manage/calls/:id/talks?page&limit&search` | Propostas paginadas com `origin, consentAt, createdAt` |
| `DELETE /c4p/manage/calls/:id/talks/:talkId` | Remove proposta (cascade em votos) + audit |
| `GET /c4p/manage/calls/:id/evaluators` | Designations da campanha com `member { id, name, handle, avatarUrl }`, `status, since` |
| `POST /c4p/manage/calls/:id/evaluators` | `{ handleOrEmail }` → resolve membro (404 se não existe/inativo); já `active` → 409; já `pending` → retorna a existente (idempotente); `removed/ended` → nova linha `pending`. E-mail de convite fire-and-forget |
| `DELETE /c4p/manage/calls/:id/evaluators/:designationId` | `removed` (revoke) + audit; **votos permanecem** e continuam contando |
| `GET /c4p/manage/calls/:id/dashboard` | `{ totals: { talks, evaluators, votes, expected, completionPercent }, progressByEvaluator: [{ designationId, member {name,handle}, done, total, complete }], ranking: [{ talkId, position, title, speakerName, track, level, avgTotal, votesCount, avgCriteria, selected }], criteriaAverages: [{ key, label, average }], byTrack: [{ value, count }], byLevel: [{ value, count }] }` — `expected = talks × evaluators active`; `complete = done === total` |
| `GET /c4p/manage/calls/:id/report` | Matriz completa para o PDF: dados da campanha, critérios, ranking com médias por critério e votos por avaliador com comentários |
| `POST /c4p/manage/calls/:id/finalize` | **Só admin.** `{ talkIds: uuid[] }` → dedup + interseção com propostas da campanha; vazio após interseção → 400 "Nenhuma proposta válida selecionada."; grava `closed + selectedTalkIds + finalizedAt`; dispara e-mails de resultado (abaixo) fire-and-forget; audit |
| `POST /c4p/manage/calls/:id/reopen` | **Só admin.** Volta a `open`, limpa `selectedTalkIds` e `finalizedAt`; audit |

## Fluxos ponta a ponta

1. **Abertura**: gestor cria (`draft`) → revisa critérios/janela → `PATCH status=open`. Antes de abrir, a campanha não aparece na vitrine nem aceita submissão.
2. **Submissão**: visitante acessa `/c4p/<slug>/submeter` (página gerada do snapshot) → a ilha confirma ao vivo (`GET /c4p/public/calls/:slug`) que a chamada aceita submissões → preenche, aceita o consentimento LGPD, resolve o Turnstile → POST → 201 → painel de confirmação (a confirmação também chega por e-mail).
3. **Curadoria**: gestor importa CSV (opcional) e/ou recebe submissões públicas → convida avaliadores por handle/e-mail → cada avaliador aceita em `/c4p/avaliar` → vota proposta a proposta em `/c4p/avaliar/votar?call=<uuid>` (sliders por critério + comentário, salvamento por proposta, upsert livre enquanto `open`) → gestor acompanha o dashboard.
4. **Finalização**: admin marca as selecionadas → `finalize` → campanha `closed`, e-mails de resultado a todos os palestrantes com e-mail → relatório PDF gerado no cliente pela aba Finalização. Reabrir (`reopen`) desfaz a seleção e devolve a votação.
5. **Resultado**: se `publicResults`, `/c4p/<slug>/resultado` lista aprovadas (título, palestrante, trilha, nível) — nunca notas nem comentários.

## E-mails transacionais

Três templates novos em `default-templates.ts` (editáveis no admin, pattern E2). `EmailTemplateContext` ganha campos opcionais — `c4pCallName?`, `c4pTalkTitle?`, `c4pResultStatus?`, `c4pActionUrl?` — mapeados em `contextValues` com default `''` (nenhum template existente muda):

| Template ID | Quando | Variáveis |
|---|---|---|
| `c4p-submission-confirmation` | Após submissão pública (201) | `attendeeName` (palestrante), `c4pCallName`, `c4pTalkTitle` |
| `c4p-evaluator-invite` | Convite de avaliador | `attendeeName` (membro), `c4pCallName`, `c4pActionUrl` = `<FRONTEND_URL>/c4p/avaliar` |
| `c4p-talk-result` | Finalização, por proposta com e-mail | `attendeeName` (palestrante), `c4pCallName`, `c4pTalkTitle`, `c4pResultStatus` (`aprovada`/`não aprovada`), `c4pActionUrl` = `/c4p/<slug>/resultado` se `publicResults`, senão `''` |

Envios via `EmailService.sendTemplate` (fila global serializada, `skipped` sem SMTP, nunca lança). Chamadas em fire-and-forget com `.catch(log)` — falha de e-mail nunca desfaz a operação principal (pattern mentoria).

## Importação CSV (Google Forms)

Parser novo `c4p/csv.ts` usando um **tokenizador genérico extraído** para `common/csv-tokenizer.ts` (mesma lógica manual de `events/csv.ts`: delimitador `;`/`,` detectado pelo header, aspas com escape `""`, BOM, RFC 4180; `events/csv.ts` passa a importar de lá — seus testes existentes devem seguir verdes). O parser de eventos **não** muda de comportamento.

Mapeamento de cabeçalhos (match exato após trim; primeira variante presente vence — portado do sistema externo):

| Campo | Cabeçalhos reconhecidos |
|---|---|
| speakerName | `Nome Completo`, `Nome` |
| speakerEmail | `Email`, `E-mail`, `Endereço de e-mail` |
| speakerPhone | `WhatsApp (com DDD)`, `WhatsApp`, `Telefone` |
| speakerRole | `Cargo e Empresa`, `Cargo` |
| linkedin | `LinkedIn`, `Linkedin` |
| spokeBefore | `Já palestrou antes?` |
| title | `Título da Palestra`, `Título` |
| summary | `Resumo da palestra`, `Resumo` |
| level | `Nível`, `Nivel` |
| track | `Tema/trilha`, `Trilha`, `Tema` |
| bio | `Bio curta`, `Bio` |
| photoUrl | `Foto` |
| extraNotes | `Algo mais que a curadoria deveria saber?`, `Observações`, `Observacoes` |

Regras: colunas não mapeadas (ex.: `Carimbo de data/hora`) são ignoradas; linha precisa de `speakerName` e `title` não-vazios, senão vai para `skipped` com `line` e `reason`; e-mail presente deve ser válido, senão a linha é recusada no `skipped`; `spokeBefore` mapeia sim/yes/true/1 → `true`, não/nao/no/false/0 → `false`, demais → `null`; limite de 500 linhas; importadas como `origin='csv_import'`, `consentAt=null` (consentimento registrado na política de privacidade da fonte — Google Forms); `speakerName`+`title` duplicados no arquivo são importados (a curadoria remove).

## Turnstile com ação própria

`TurnstileGuard` hoje fixa a ação `guest_claim`. Generalização mínima: decorator `@TurnstileAction(action: string)` (metadata via `Reflector`, default `'guest_claim'` — comportamento atual inalterado para `guest-claim`). A submissão pública usa `@TurnstileAction('c4p_submission')`; o frontend passa `action="c4p_submission"` ao `TurnstileField` (prop já existe). Sem secret: dev aceita token `development`, prod falha fechada (inalterado).

## Snapshot público, sync e proxy

`GET /c4p/public/snapshot` retorna:

```json
{
  "generatedAt": "<ISO>",
  "calls": [{
    "slug": "...", "name": "...", "description": null,
    "status": "open|closed",
    "submissionOpenAt": null, "submissionCloseAt": null,
    "publicResults": false, "finalizedAt": null,
    "community": { "slug": "...", "name": "..." } | null,
    "event": { "slug": "...", "title": "..." } | null,
    "results": { "talks": [{ "title": "...", "speakerName": "...", "track": null, "level": null }] } | null
  }]
}
```

Inclui campanhas `open` (vitrine + submissão) e `closed` com `publicResults` (resultado). `results` só existe quando `closed && publicResults`, contendo **somente** `selectedTalkIds` e os 4 campos públicos. Nunca inclui notas, comentários, e-mails, telefones ou IDs internos desnecessários.

- `scripts/sync-c4p.mjs` (env `C4P_API_URL`): valida a coleção inteira, grava `static/c4p/index.json` atomicamente (tmp + rename), preserva o anterior em erro, pula escrita se byte a byte igual; fora do agregador `npm run sync`. Workflow `sync-c4p.yml` (`33 * * * *` + dispatch) commita só se mudou. `copy-snapshots.mjs` passa a copiar `static/c4p/`.
- Proxy (`src/lib/api-proxy-paths.ts`): prefixos estreitos `/c4p/public/`, `/c4p/manage/`, `/c4p/evaluator/` + exceção exata `/c4p/index.json`. Não colide com as páginas `/c4p`, `/c4p/<slug>/submeter`, `/c4p/<slug>/resultado`, `/c4p/avaliar` (slug reservado impede `public`/`manage`/`evaluator`; `avaliar` não é prefixo de API).
- Loader `src/lib/c4p.ts`: leitura em build com validação defensiva item a item e fallback `emptyIndex()` (pattern `src/data/mentors.ts` — build nunca quebra sem snapshot).

## Papéis e permissões

| Ação | Público | Membro | Escopo | Aprovação/admin |
|---|---|---|---|---|
| Ver vitrine/resultado público | L | L | L | — |
| Submeter proposta | E (com consentimento + Turnstile) | E | — | — |
| Gerir campanha (CRUD, import, convites, dashboard, relatório) | — | — | E: `admin`, `event_organizer`, `diretor`; `responsible` @ community dona | — |
| Avaliar/votar | — | — | E: `evaluator` @ campanha (`pending` → aceite → `active`) | quem abre a campanha convida |
| Finalizar/reabrir + e-mails de resultado | — | — | — | **só `admin`** |

Avaliador não é role global: vive como designation `evaluator @ c4p_campaign` (`pending` no convite, `active` no aceite, `removed` na remoção), 1 ativo por campanha por membro (índice parcial novo + checagem no service). Não existe tabela `c4p_evaluators`.

## Segurança e LGPD

- **PII do externo é proibida** em seeds, fixtures e testes (a pasta `code-to-analyze/` permanece gitignored). Testes usam dados sintéticos.
- Submissão pública coleta nome/e-mail/telefone/LinkedIn de não-membros: `consent: true` obrigatório grava `consentAt`; checkbox com finalidade declarada; remoção sob solicitação via contato@codaqui.dev. Inventário `docs/modules/privacy/treatments.md` atualiza a linha "Palestrante C4P" (hoje "(futuro)") e a página `/sobre/privacidade` ganha o perfil.
- Notas e comentários são restritos (gestão); snapshot, vitrine e resultado os excluem por construção (whitelist de campos).
- Turnstile + throttle estrito (5/min) na submissão; validação de `linkedin`/`photoUrl` como HTTPS sem credenciais (pattern da validação de link de announcements — **não** a allowlist de comprovantes do StorageModule, que serve a outro fim).
- `slug` reservado impede colisão de rotas/proxy; uploads limitados a 500 linhas / 6 mb (limite global de `express.text`).

## Auditoria

Novas ações em `AuditAction` (coluna `varchar(64)`, sem migration), adicionadas a `GOVERNANCE_ACTIONS` (permanentes, sem IP): `c4p_call.created`, `c4p_call.updated`, `c4p_call.finalized`, `c4p_call.reopened`, `c4p_talk.imported`, `c4p_talk.deleted`, `c4p_evaluator.invited`, `c4p_evaluator.removed`. Convite/aceite do avaliador já gera `designation.granted/confirmed/revoked` no módulo de designations. Submissão pública **não** gera audit (anonima; `consentAt` + `email_logs` bastam).

## Fora de escopo

- Selo "C4P aberto" na página do evento e grade alimentada pelas aprovadas (pós-1.0.0, conforme anexo).
- Fila persistente para e-mails de resultado (fire-and-forget basta no volume atual; reavaliar se virar rotina).
- Avaliador sem conta GitHub (risco 12 do plano-mãe — pattern de convidado por token, se a diretoria exigir).
- Recusa de convite na UI (basta ignorar; gestor remove), upload de foto (photoUrl é link), comentário do avaliador na proposta para o palestrante.
- Snapshot de comunidade por tenant (campanhas de comunidades integradas aparecem no portal; o build do tenant pode vir depois).

## Testes, gates e rollout

- **Unitários (jest)**: scoring (pesos, critérios parciais, ranking, sem voto), parser CSV (delimitadores, aspas, variantes de cabeçalho, linhas inválidas, `spokeBefore`, limites), calls service (slug reservado, critérios, congelamento, máquina de status), submissão (validações, janela, 409, consentimento, e-mail), import (mapeamento, skipped), avaliadores (idempotência, 409, reconvite, e-mail, aceite), votos (upsert insert/update, guards, chaves/valores), dashboard (agregações), finalize/reopen (só admin, interseção, e-mails, audit), controllers (guards, shapes, 404), TurnstileGuard com ação customizada, templates (render com variáveis novas).
- **E2E PostgreSQL real** (`test/c4p.e2e-spec.ts`): migration 049 down/up; jornada completa criar→abrir→submeter→convidar→aceitar→votar (upsert 2×)→dashboard→finalizar (e-mails `skipped`)→resultado público; permissões (organizador não finaliza, não-avaliador não vota, estranho não gerencia, responsável de outra comunidade não gerencia); índice único de avaliador ativo; snapshot sem vazamento.
- **Frontend (vitest)**: loader do snapshot (fallback, validação), ilhas (form de submissão, votação, convite, finalização), montagem dos dados do PDF, proxy paths.
- **Scripts**: `sync-c4p.mjs` (atomicidade, payload, erro preserva, inalterado byte a byte).
- **Gates**: `npm run build && npx jest` (backend), `npm run test:scripts`, `make astro-verify`, `make astro-verify-tenants` (proxy paths é compartilhado), SonarCloud.
- **Rollout**: develop → PR de acompanhamento → PR para main → release **v1.0.0-backend** (migration 049 roda em produção) → redeploy manual no Coolify → sync inicial do snapshot → deploy do frontend → campanha piloto real → ADR 012 marcada como implementada.
